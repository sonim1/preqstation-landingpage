PreqStation is an execution platform for AI-agent-driven development workflows. It bridges developers and coding agents through a task queue, a web app, and agent-facing APIs.

If you want the product story before the system diagram, read [Product Philosophy](/guide/getting-started/philosophy) first.

## Recommended First Step

If you're starting PreqStation from scratch, begin with [Quick Start](/guide/getting-started/quick-start). It starts with `npx -y @sonim1/preqstation@latest install`, then checks local runtime, MCP, and project setup. If you are self-hosting the web app or validating migrations, use [Web App Setup](/guide/web-app/setup).

## Setup Path Order

- **CLI Default Setup** — [Quick Start](/guide/getting-started/quick-start) for the fastest CLI installer path
- **Direct CLI Dispatch** — [Direct Dispatch](/guide/getting-started/direct-dispatch) when the operator host should launch the task immediately
- **Worker-Only Setup** — [Worker Installation](/guide/skill/installation) when you want manual Claude, Codex, or Gemini worker setup
- **Dispatcher Setup** — add queued delivery only if you need it from the web app: [OpenClaw Installation](/guide/openclaw/setup) or [Telegram Integration](/guide/web-app/telegram)
- **Web App Setup** — [Web App Setup](/guide/web-app/setup) for self-hosting, migrations, and first-login details

## Core Systems and Dispatcher Paths

PreqStation separates any queued dispatcher path from the task engine:

	<Card title="PreqStation Web App" icon="setting">

	</Card>
</CardGrid>

## Data Flow

### Task Creation and Notification

```text
User creates task in the Kanban UI
  -> PreqStation stores it in PostgreSQL
  -> user optionally chooses a dispatch target
  -> PREQ queues Telegram/OpenClaw relay only when that path is needed
```

### Dispatcher Target vs Engine

- `dispatch_target=telegram` means the user chose **Send to Telegram** or copied a Telegram/OpenClaw command.
- Direct CLI dispatch starts on the operator host with [`preqstation run`](/guide/getting-started/direct-dispatch), so it does not need a Telegram, Hermes, or OpenClaw relay.
- `engine=claude-code | codex | gemini-cli` stays separate from the dispatcher target and decides which local CLI actually runs the task.

### Agent Trigger via OpenClaw

```text
Telegram / OpenClaw path:
  developer chooses Send to Telegram or hands the copied command to OpenClaw
    -> OpenClaw resolves project + task + engine
    -> creates an isolated git worktree
    -> launches the requested coding agent
```

### Agent Execution and Status Reporting

<Mermaid
  chart={`

```text
Agent lifecycle:
  inbox -> preq_plan_task -> todo
  todo or hold -> implement -> preq_complete_task -> ready
  ready -> verify -> preq_review_task -> done
  any blocked step -> preq_block_task -> hold
```

## Tech Stack

| Layer      | Technology                                  |
| ---------- | ------------------------------------------- |
| Framework  | Next.js 16 (App Router)                     |
| UI         | React 19, Mantine 8, Tabler Icons, Recharts |
| ORM        | Drizzle ORM                                 |
| Database   | PostgreSQL (Row Level Security)             |
| Validation | Zod                                         |
| Auth       | Session cookies (HMAC-signed), bcryptjs     |

<Aside>
All data is owner-scoped via PostgreSQL Row Level Security. PreqStation is designed for single-developer use.
</Aside>
