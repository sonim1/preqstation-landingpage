---
title: Direct Dispatch
description: Launch a PREQ task directly from the CLI on an operator host.
---

Direct dispatch launches a worker from the `preqstation` CLI without routing the request through OpenClaw, Hermes, or Telegram. Use it when you are already on the local operator host, project mapping is available, and you want to start a detached task run immediately.

Direct dispatch does not replace task tracking. The task still belongs to PreqStation, and the worker still reports lifecycle results back through the PreqStation MCP/task tools.

## When to Use It

Use direct dispatch when:

- you are on the machine that should run the selected worker CLI
- the project is already mapped with `preqstation setup auto` or `preqstation setup set`
- you want a local detached worker run
- you do not need web, chat, Telegram, Hermes, or OpenClaw relay behavior for this run

If the web app or a chat relay should trigger the work remotely, use the matching dispatcher path instead.

## Core Command

```bash
preqstation run \
  --project-key PROJ \
  --task-key PROJ-327 \
  --objective implement \
  --engine codex \
  --branch-name task/proj-327-example
```

Fields:

| Field | Meaning |
|---|---|
| `--project-key` | PREQ project key, such as `PROJ`. |
| `--task-key` | Task ticket to run, such as `PROJ-327`. |
| `--objective` | The lifecycle objective for the run, such as `implement`, `review`, or an ask-style objective supported by the task source. |
| `--engine` | Worker runtime: `claude-code`, `codex`, or `gemini-cli`. |
| `--branch-name` | Isolated branch/worktree name for the run. Use placeholders or task-derived names, not private repository names. |

The CLI turns those flags into the same dispatch intent shape used by the adapter paths, then resolves the local project and launches the selected worker from the operator host.

## Message and JSON Entrypoints

Use `run-message` when you want to test or forward the same message shape an integration would send:

```bash
preqstation run-message --message 'preqstation implement PROJ-327 using codex'
```

Use `run-json` for webhook or payload replay automation:

```bash
preqstation run-json --payload /path/to/preq-webhook-payload.json
```

Keep replay payloads scrubbed. Do not store real tokens, private project URLs, chat IDs, or user credentials in examples or shared fixtures.

## Direct CLI vs Other Dispatch Paths

| Path | Use when | What starts the worker |
|---|---|---|
| Web app | You want to create, manage, dispatch, and review tasks in the PreqStation UI. | The selected dispatch action or later operator handoff. |
| Telegram / Hermes | You want remote or chat-triggered delivery into a host with tools enabled. | Hermes receives the message and launches the requested worker. |
| OpenClaw | You want OpenClaw gateway dispatch, copied OpenClaw commands, or `/preqsetup` mapping support. | OpenClaw resolves the request and launches the worker. |
| Direct CLI | You are already on the operator host and want to run immediately. | `preqstation run`, `run-message`, or `run-json`. |

The dispatcher target and the engine remain separate. A direct CLI run can still choose `claude-code`, `codex`, or `gemini-cli` as the worker engine.

## Prerequisites

- PREQ CLI installed globally, or available through `npx -y @sonim1/preqstation@latest`.
- `preqstation doctor` is clean enough for the selected runtime.
- Project mapping exists through `preqstation setup auto` or `preqstation setup set`.
- The selected worker CLI is installed and executable from the host process.
- Remote `/mcp` OAuth is complete for runtimes that use the recommended MCP path.

## Result Expectations

A direct dispatch run follows the same high-level execution contract as the adapter paths:

1. The CLI resolves the project, task, objective, engine, and branch/worktree name.
2. It creates or uses an isolated worktree/branch where applicable.
3. It launches the selected worker runtime from the operator host.
4. The worker reads the generated PREQ prompt and executes the task lifecycle.
5. The worker reports notes, tests, branch or PR evidence, and final status back to PreqStation.
6. You review the result in PreqStation before moving the task through the rest of the workflow.

## Troubleshooting

- Start with [PREQ CLI](/guide/getting-started/preq-cli) for install, mapping, `status`, and `doctor` commands.
- Use [Troubleshooting](/guide/reference/troubleshooting) when project mapping, MCP registration, or runtime detection is unclear.
- Use [OpenClaw Installation](/guide/openclaw/setup) if you actually need OpenClaw gateway or chat dispatch.
- Use [Telegram Integration](/guide/web-app/telegram) if Hermes or Telegram should deliver the request.
