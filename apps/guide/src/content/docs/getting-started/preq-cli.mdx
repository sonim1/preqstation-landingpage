The PREQ CLI is the public npm package `@sonim1/preqstation` and the user-facing command `preqstation`.

Use it on the local machine or host that will execute or dispatch PREQ tasks. It prepares operator-host setup for the pieces you choose: Hermes entrypoints, worker runtime detection, detached worktree state, logs, and project mappings.

The CLI does not replace the web app. The web app remains the task and control plane for creating tasks, dispatching work, and reviewing results.

## Recommended First Run

For a temporary first run, use `npx`:

```bash
npx -y @sonim1/preqstation@latest install
npx -y @sonim1/preqstation@latest status
```

`install` is idempotent. Run it again when you want the guided installer to check what is already present and offer missing setup steps.

## Choose `npx` or Global Install

| Use | Best when | Command |
|---|---|---|
| `npx -y @sonim1/preqstation@latest ...` | You are trying PREQ once, debugging a host, or avoiding global packages | `npx -y @sonim1/preqstation@latest status` |
| `npm install -g @sonim1/preqstation` | This machine will regularly execute queued work or host Hermes dispatch | `preqstation status` |

## Global Install

If this host will operate PREQ regularly, install the command globally:

```bash
npm install -g @sonim1/preqstation
preqstation install
preqstation status
```

## Lifecycle Commands

Use these commands to keep the operator host current and inspectable:

```bash
preqstation update
preqstation status
preqstation doctor
preqstation status --json
preqstation doctor --json
preqstation uninstall
preqstation uninstall hermes
```

`update` refreshes installed CLI surfaces and host support. `status` and `doctor` are read-only checks; use the JSON variants when another script or monitoring process needs structured output.

`uninstall` removes selected installed surfaces. Project mappings and OAuth cache are intentionally separate from those installed surfaces, so do not rely on uninstall as a credential or mapping reset.

## Reading Status Output

Start with these three read-only checks before editing runtime files by hand:

```bash
preqstation status
preqstation doctor
preqstation setup status
```

Use the output like this:

| Check | Healthy signal | If it is missing |
|---|---|---|
| CLI availability | `preqstation` resolves or the `npx` command runs | Re-run `install`, then confirm Node.js 22+ is active |
| Worker runtime | Claude Code, Codex, or Gemini CLI is detected | Install the worker CLI or fix the host `PATH` |
| Direct-client MCP compatibility | the `preqstation` server points at `https://<your-domain>/mcp` when you opted into that setup | Register MCP again or complete browser OAuth |
| Project mapping | each project key resolves to an absolute local path | Run `preqstation setup auto` or `preqstation setup set` |

## Project Mapping

Project mapping tells the dispatcher where each PREQ project checkout lives on the operator host.

```bash
preqstation setup auto
preqstation setup auto PROJ=https://github.com/example/project
preqstation setup set PROJ /absolute/path/to/project
preqstation setup status
preqstation setup unset PROJ
```

`setup auto` scans `PREQSTATION_REPO_ROOTS` when set, otherwise `~/projects`. It matches local git origins against PREQ project repository URLs. Shared mappings are stored in `~/.preqstation/projects.json`.

Use `setup set` when the checkout is outside the scanned roots or when you want to pin a project key to an exact path.

## Integration Installs

Install the Hermes dispatch entrypoint only on hosts that should receive Telegram dispatches:

```bash
preqstation install hermes
preqstation status hermes
```

Hermes is a dispatch host. It receives work, resolves the project, creates the worktree, and launches the selected worker runtime. It is separate from the task engine, which is still Claude Code, Codex, or Gemini CLI.

For Hermes profile maintenance, sync the installed Hermes support after changing the target profile or after upgrading the CLI:

```bash
preqstation sync hermes
preqstation sync hermes --force
```

If `install`, `update`, or `sync hermes` reports that a gateway restart is required, restart Hermes before the next dispatch:

```bash
hermes gateway restart
```

Hermes must have terminal/tool execution enabled. A chat-only Hermes profile cannot create worktrees or launch local worker CLIs.

## Manual Worker Setup

Use the CLI first for normal local setup. Manual MCP registration and worker-only setup remain available when you intentionally want direct-client PREQ tool access without detached dispatch.

Token and API key paths are compatibility paths for shell helpers and older local bridges. The recommended remote `/mcp` flow uses OAuth where the runtime supports it.
