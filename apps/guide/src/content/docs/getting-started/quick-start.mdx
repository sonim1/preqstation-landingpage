Quick Start is the first-run path. Keep it focused on one outcome: this machine can run PREQ work through your chosen agent runtime.

## Recommended Setup Path

Run the PREQ CLI installer first. It prepares the local operator host, detects worker runtimes, installs selected dispatch entrypoints, and creates project mappings.

```bash
npx -y @sonim1/preqstation@latest install
npx -y @sonim1/preqstation@latest status
```

The installer is safe to run again. It checks what is already installed and offers only the missing setup steps.

## What Success Looks Like

After the first run, `status` should tell you:

- the `preqstation` command is available or the `npx` command is usable
- at least one worker runtime is detected, such as Claude Code, Codex, or Gemini CLI
- project mappings are present if this host will receive queued dispatches
- optional direct-client `/mcp` compatibility is registered only if you chose that setup

If any line is unclear, run the deeper read-only check:

```bash
npx -y @sonim1/preqstation@latest doctor
```

For the full command reference, including global install, `update`, `doctor`, JSON output, project mapping, targeted Hermes installs, Hermes sync, and uninstall, see [PREQ CLI](/guide/getting-started/preq-cli/).

## Manual Direct-Client MCP Setup

Use this only when you intentionally want an agent client to call PREQ MCP tools directly. Detached dispatch workers use the PREQ CLI instruction file and task commands instead.

```bash
# Claude Code
claude mcp add -s user --transport http preqstation https://<your-domain>/mcp

# Codex
codex mcp add preqstation --url https://<your-domain>/mcp

# Gemini CLI
gemini mcp add --scope user --transport http preqstation https://<your-domain>/mcp
```

Complete the browser OAuth flow when prompted. Codex often starts this during `add`, Claude Code commonly starts it on the first real request or `claude mcp get preqstation`, and Gemini CLI may start it during registration or the first real tool call.
