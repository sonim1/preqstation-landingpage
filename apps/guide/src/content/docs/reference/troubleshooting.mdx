The standard PreqStation setup path starts with the PREQ CLI. Use the remote `/mcp` sections only when troubleshooting optional direct-client MCP compatibility, and use the token-based steps only for shell-helper mode or the legacy local stdio bridge.

## Symptom Map

| Symptom | Start here | First command |
|---|---|---|
| No PREQ tools appear in Claude, Codex, or Gemini | Remote MCP & OAuth Issues | `preqstation status` |
| Browser auth never completes | Remote MCP & OAuth Issues | `claude mcp get preqstation` or runtime equivalent |
| Dispatch cannot find the project checkout | Project Mapping Issues | `preqstation setup status` |
| Hermes receives a message but does not run work | Dispatcher Execution Issues | `preqstation status hermes` |
| Worker CLI works in your terminal but not in Hermes | Worktree & Git Issues | `preqstation doctor` |
| `npm install` fails in a task worktree | Build & Compilation Errors | inspect the package manager log |
| Shell helper returns `401 Unauthorized` | Legacy Compatibility Issues | confirm `PREQSTATION_TOKEN` |

## Start with Doctor and Status

Run the read-only CLI checks before manual runtime debugging:

```bash
preqstation doctor
preqstation status
preqstation doctor --json
preqstation status --json
```

Use the normal output when you are debugging interactively. Use the JSON output when you need to paste structured diagnostics into a report, script, or monitoring system.

Common next steps from the checks:

- Fix server URL or `/mcp` endpoint warnings before re-registering worker runtimes.
- Finish OAuth if you intentionally registered direct-client MCP but the runtime is unauthenticated.
- Refresh project mappings with `preqstation setup status`, `preqstation setup auto`, or `preqstation setup set`.
- Fix missing worker executables such as `claude`, `codex`, or `gemini` on the host process `PATH`.
- Restart Hermes after changing environment variables, because long-running host processes inherit their environment at launch.
- Inspect global CLI failures in `~/.preqstation/logs/error.log`; pass `--debug` or set `PREQSTATION_DEBUG=1` when you need stack traces.

## Optional Remote MCP & OAuth Issues

### Server URL or remote `/mcp` endpoint looks wrong

**Symptom:** `doctor` reports a missing server URL, MCP registration points to the app root, or runtime setup succeeds but no PREQ tools appear.

**Solutions:**

1. Confirm the web app URL is the deployed PreqStation service URL:
```bash
preqstation status
```

2. Register the MCP endpoint with the `/mcp` suffix:
```bash
claude mcp add -s user --transport http preqstation https://<your-domain>/mcp
codex mcp add preqstation --url https://<your-domain>/mcp
gemini mcp add --scope user --transport http preqstation https://<your-domain>/mcp
```

3. If an old app-root URL was registered, remove and re-add the runtime MCP server.

### Remote MCP stays unauthenticated or tools do not appear

**Symptom:** Claude Code shows `Needs authentication`, Codex or Gemini CLI cannot finish setup, or PREQ tools do not appear after registration.

**Solutions:**

1. Confirm you registered the remote endpoint, not the legacy local script:
```bash
claude mcp add -s user --transport http preqstation https://<your-domain>/mcp
# or:
codex mcp add preqstation --url https://<your-domain>/mcp
# or:
gemini mcp add --scope user --transport http preqstation https://<your-domain>/mcp
```

2. Make sure the URL ends with `/mcp`:
```bash
# ❌ Bad: https://your-domain.com
# ✅ Good: https://your-domain.com/mcp
```

3. Trigger the first real connection:
```bash
claude mcp get preqstation
# or:
codex mcp get preqstation
# or:
gemini mcp list
```

4. Complete the browser login flow when prompted.

5. If the client still looks stuck, remove and re-add the server:
```bash
claude mcp remove preqstation
claude mcp add -s user --transport http preqstation https://<your-domain>/mcp
# or:
codex mcp remove preqstation
codex mcp add preqstation --url https://<your-domain>/mcp
# or:
gemini mcp remove preqstation
gemini mcp add --scope user --transport http preqstation https://<your-domain>/mcp
```

## Legacy Compatibility Issues

### Legacy local MCP bridge fails to start

**Symptom:** `Error: Cannot find module` or local stdio bridge never boots.

**Solutions:**

1. Verify Node.js is installed:
```bash
node --version  # Should be 22+
```

2. Check the script path is absolute (not relative):
```bash
# ❌ Bad: "args": ["./preqstation-mcp-server.mjs"]
# ✅ Good: "args": ["/Users/kendrick/projects/preqstation-skill/scripts/preqstation-mcp-server.mjs"]
```

3. Verify the script file exists:
```bash
ls -la /path/to/preqstation-skill/scripts/preqstation-mcp-server.mjs
```

4. Check environment variables are set:
```bash
echo $PREQSTATION_API_URL
echo $PREQSTATION_TOKEN
```

5. Re-register the legacy local bridge if needed:
```bash
claude mcp remove preqstation
claude mcp add -s user \
  --env='PREQSTATION_API_URL=https://...' \
  --env='PREQSTATION_TOKEN=preq_...' \
  preqstation -- node /path/to/preqstation-mcp-server.mjs
```

### Tools appear in MCP but shell-helper mode or the legacy local bridge returns errors

**Symptom:** `preq_list_tasks` or other tools fail with `401 Unauthorized` while using shell-helper mode or the legacy local bridge.

1. Verify token format (should start with `preq_`):
```bash
echo $PREQSTATION_TOKEN  # Should output: preq_xxxxxxxxx
```

2. Verify token is not expired:
- Go to the PreqStation web app → Settings → API Keys
- Check token creation date and expiration
- Generate a new token if needed

3. Test connectivity directly:
```bash
curl -H "Authorization: Bearer $PREQSTATION_TOKEN" \
  "$PREQSTATION_API_URL/api/health"
# Should return: {"status":"ok"}
```

4. Verify API URL is correct (must include protocol):
```bash
# ❌ Bad: "preqstation-lp.vercel.app"
# ✅ Good: "https://preqstation-lp.vercel.app"
```

5. If you still need the token-based setup reference, see [Legacy API Keys](/guide/web-app/api-keys/) and [Environment Variables](/guide/reference/environment-variables/).

### "Invalid token" error on every MCP call in shell-helper mode or the legacy local bridge

**Symptom:** Token auth fails even with a correct-looking token while using shell-helper mode or the legacy local bridge. If you are on the recommended remote `/mcp` path, return to the Remote MCP & OAuth section above instead.

<Tabs>
<TabItem label="Cause: Expired Token">
**Check:** In the PreqStation web app, go to Settings → API Keys and check expiration date.

**Fix:** Generate a new token:
1. Click "New Token"
2. Copy the new token value
3. Update `PREQSTATION_TOKEN` environment variable
4. Re-register MCP server with new token
</TabItem>
<TabItem label="Cause: Token Revoked">
**Check:** List tokens in Settings → API Keys to see if token is still there.

**Fix:** Generate a fresh token (old one may have been revoked).
</TabItem>
<TabItem label="Cause: Wrong Bearer Format">
**Check:** Environment variable and MCP config have exact token value.

**Problem:** Token was pasted with extra spaces or quotes.

**Fix:**
```bash
# ❌ Bad:
export PREQSTATION_TOKEN=" preq_xxxxx " # spaces!

# ✅ Good:
export PREQSTATION_TOKEN="preq_xxxxx"   # no extra spaces
```
</TabItem>
</Tabs>

## Worktree & Git Issues

### CLI setup, project mapping, or dispatcher health is unclear

**Symptom:** A dispatch cannot find a project, the worker runtime is not detected, or you are unsure whether Hermes support was installed.

**Solutions:**

1. Start with the CLI diagnostics:
```bash
preqstation doctor
preqstation status
```

2. Confirm project mappings:
```bash
preqstation setup status
preqstation setup auto PROJ=https://github.com/example/project
preqstation setup set PROJ /absolute/path/to/project
```

3. Check CLI runtime state paths:
```bash
echo $PREQSTATION_DISPATCH_HOME
echo $PREQSTATION_PROJECTS_FILE
echo $PREQSTATION_WORKTREE_ROOT
```

4. If the run launched but failed later, inspect the detached runtime log inside the task worktree:
```bash
tail -100 .preqstation-dispatch/claude-code.log
tail -100 .preqstation-dispatch/codex.log
tail -100 .preqstation-dispatch/gemini-cli.log
```

### Worker CLI executable is missing

**Symptom:** `doctor` reports that `claude`, `codex`, or `gemini` cannot be found, or a dispatch starts but the worker process fails immediately.

**Solutions:**

1. Check the executable from the same shell or host process that runs dispatch:
```bash
command -v claude
command -v codex
command -v gemini
```

2. Install or update the missing runtime, then rerun:
```bash
preqstation doctor
preqstation status
```

3. If the command exists in your interactive shell but not in Hermes, fix the host process environment and restart that host.

### PATH or session-scoped Node setup is not inherited

**Symptom:** The runtime works in a terminal, but Hermes or a detached PREQ run cannot find `node`, `npm`, `preqstation`, `claude`, `codex`, or `gemini`.

**Solutions:**

1. Prefer globally available executables for operator-host dispatch.
2. Avoid relying only on session-scoped version manager state, such as an interactive `fnm use` that was not exported to the host process.
3. Restart Hermes after changing shell profile files, PATH, Node versions, or globally installed CLIs.
4. Rerun:
```bash
preqstation doctor
```

### Hermes tools or terminal execution are unavailable

**Symptom:** Hermes receives the message, but cannot create worktrees or launch the selected worker.

**Solutions:**

1. Use a Hermes profile with terminal/tool execution enabled. A chat-only profile cannot run PREQ tasks.
2. Sync Hermes support after changing profiles or upgrading the CLI:
```bash
preqstation sync hermes
preqstation status hermes
```

3. Confirm project mapping and runtime health:
```bash
preqstation setup status
preqstation doctor
```

### Worktree conflicts or cleanup failures

**Symptom:** `fatal: invalid reference: <branch>` or stale worktree directory

**Solutions:**

1. List existing worktrees:
```bash
git -C <project_cwd> worktree list
```

2. Remove stale worktrees:
```bash
git -C <project_cwd> worktree remove <path> --force
git -C <project_cwd> worktree prune
```

3. If worktree is locked:
```bash
git -C <project_cwd> worktree unlock <path>
git -C <project_cwd> worktree remove <path> --force
```

4. Check for corrupted `.git/worktrees/` directory:
```bash
ls -la <project_cwd>/.git/worktrees/
# If corrupted, delete the lock file:
rm <project_cwd>/.git/worktrees/<worktree_name>/locked
```

### Remote push verification fails

**Symptom:** `failed: ... - Remote push verification failed`

<Tabs>
<TabItem label="Issue: Branch not pushed">
**Cause:** `deploy_commit_on_review=true` requires successful push before completing task.

**Check:**
```bash
git -C <project_cwd> branch -r | grep <branch_name>
# Or:
git ls-remote --heads origin <branch_name>
```

**Fix:**
1. Manually push the branch:
```bash
git -C <project_cwd> push origin <branch_name>
```

2. Then run `preqstation task complete <task_id> --json-file result.json` again
</TabItem>
<TabItem label="Issue: Wrong branch name">
**Cause:** Branch created locally but with different name.

**Check:** Compare local vs. resolved branch name:
```bash
git -C <project_cwd> branch
# Expected: preqstation/PROJ/feature-name
```

**Fix:** Push with the correct name or include the final branch in the `preqstation task complete --json-file result.json` payload.
</TabItem>
</Tabs>

## Build & Compilation Errors

### "npm install" fails in worktree

**Symptom:** `npm ERR! 404 Not Found` or dependency resolution errors

<Tabs>
<TabItem label="Cause: Wrong package manager">
**Check:** Use the package manager already configured by the repo.

**Fix:** Do not delete lockfiles as a first step. Run the repo's intended install command instead:
```bash
# examples
pnpm install
npm install
yarn install
```
</TabItem>
<TabItem label="Cause: Node version mismatch">
**Check:**
```bash
node --version
cat <cwd>/.nvmrc  # If using nvm
```

**Fix:** Use correct Node version:
```bash
nvm use  # If .nvmrc exists
node --version  # Should match project requirements
```
</TabItem>
<TabItem label="Cause: Private dependencies">
**Check:** `.npmrc` credentials or `package.json` scoped packages.

**Fix:**
```bash
# Ensure .npmrc has auth token for private registry:
echo "@scope:registry=https://npm.example.com" >> ~/.npmrc
echo "//npm.example.com/:_authToken=YOUR_TOKEN" >> ~/.npmrc
```
</TabItem>
</Tabs>

## Project Mapping Issues

### "Project path not found"

**Symptom:** The dispatcher asks for a project path even though you thought it was already configured.

**Solutions:**

1. Confirm the mapping exists in the PREQ CLI project mapping file:
```bash
preqstation setup status
```

2. If missing, create or refresh it:
```bash
preqstation setup auto PROJ=https://github.com/example/project
# or:
preqstation setup set PROJ /absolute/path/to/project
```

3. If you use the sample `MEMORY.md` format as a legacy fallback, check that the row looks like:
```markdown
| key | cwd | note |
|-----|-----|------|
| proj | /absolute/path | Description |
```

4. Verify the project key matches the task prefix:
- `PRJ-284` should normally map to `prj`

5. Ensure paths are absolute (not relative):
```bash
# ❌ Bad: ./projects/example
# ✅ Good: /Users/kendrick/projects/example
```

## Dispatcher Execution Issues

### Session never completes or seems stuck

**Symptom:** Process shows no output for hours, or stuck at same log line

**Solutions:**

1. Prefer PREQ CLI diagnostics first:
```bash
preqstation status
preqstation doctor
```

2. Read the detached runtime log from the task worktree:
```bash
tail -100 .preqstation-dispatch/<engine>.log
```

3. Check for infinite loops or blocking I/O:
```bash
# Common causes:
# - npm install hung on network
# - Interactive prompts waiting for input
# - Subprocess blocking on child process
```

### "Permission denied" when accessing project files

**Symptom:** `Error: EACCES: permission denied` in worktree

**Solutions:**

1. Verify directory permissions:
```bash
ls -ld <project_cwd>
# Should be readable/writable by current user
```

2. Check worktree permissions:
```bash
ls -ld <cwd>
chmod -R u+rw <cwd>  # If needed
```

3. Ensure Git can write to worktree:
```bash
touch <cwd>/.test-write
rm <cwd>/.test-write
```

## Common Mistakes

### ❌ Forgetting to update project mappings

**Issue:** The dispatcher can't resolve project path, requires manual input each time.

**Fix:** Update the PREQ project mapping whenever you clone a new project or change paths:

```bash
preqstation setup auto PROJ=https://github.com/example/project
preqstation setup status
```

If you keep a reference `MEMORY.md` as a legacy fallback, keep that in sync too:
```markdown
| key | cwd | note |
|-----|-----|------|
| newproj | /absolute/path | Added 2026-03-06 |
```

### ❌ Using relative paths in project mappings

**Issue:** Worktree creation fails because path doesn't expand.

**Fix:** Always use absolute paths:
```bash
# Get absolute path:
pwd  # from within the project
```

### ❌ Not cleaning up old worktrees

**Issue:** Disk fills up, performance degrades.

**Fix:** Periodic cleanup:
```bash
git -C <project_cwd> worktree list
git -C <project_cwd> worktree remove <old_path> --force
git -C <project_cwd> worktree prune
```

### ❌ Expecting direct-client PREQ tools without MCP

**Issue:** `preq_*` tools are unavailable in a direct agent client because the optional MCP server was never registered.

**Fix:** For normal detached dispatch, use the PREQ CLI and the generated `.preqstation-instructions.txt`. For direct-client MCP compatibility, register the PreqStation MCP server:
```bash
claude mcp list | grep preqstation
```

Or let the CLI installer set it up:

```bash
npx -y @sonim1/preqstation@latest install
preqstation status
```

## Getting Help

If you've checked all above:

1. **Gather diagnostics:**
   ```bash
   echo "API URL: $PREQSTATION_API_URL"
   echo "Token format: ${PREQSTATION_TOKEN:0:4}... (masked)"
   node --version
   git --version
   npm --version
   preqstation status
   preqstation doctor
   ```

2. **Test basic connectivity:**
   ```bash
   curl -H "Authorization: Bearer $PREQSTATION_TOKEN" \
     "$PREQSTATION_API_URL/api/health" | jq .
   ```

3. **Check logs:**
   - Claude Code: Settings → Logs
   - PREQ CLI global errors: `~/.preqstation/logs/error.log`
   - Detached worker process: `.preqstation-dispatch/<engine>.log` inside the task worktree
   - PreqStation web app: deployment or server logs

4. **File an issue** with:
   - System info (OS, Node version)
   - Error message (full stack trace)
   - Steps to reproduce
   - Diagnostics output (without exposing tokens)
