This reference documents all environment variables used by the PreqStation web app, worker compatibility paths, and the PREQ CLI dispatcher.

## Minimal First Setup

For a normal hosted or self-hosted web app, start with only the web service variables:

```bash
AUTH_SECRET="<generate with: openssl rand -base64 48>"
DATABASE_URL="postgresql://user:pass@host/dbname"
```

Add `ALLOWED_ORIGINS` only when the app must trust additional first-party origins. Add `PREQSTATION_TOKEN` only for shell-helper mode, direct REST automation, or an older local bridge.

## PreqStation web app

Server-side variables for the main PreqStation web service. Owner credentials are no longer read from environment variables. Fresh instances create the first owner account at `/login`, and existing deployments store owner credentials in the `users` table.

| Variable | Required | Default | Purpose |
|----------|----------|---------|---------|
| `AUTH_SECRET` | Yes | — | HMAC session secret (minimum 16 characters) |
| `DATABASE_URL` | Yes | — | PostgreSQL connection string |
| `ALLOWED_ORIGINS` | No | — | Extra trusted origins for server actions and same-origin checks |
| `UNSPLASH_ACCESS_KEY` | No | — | Enables Unsplash search in the project background picker |
| `CRON_SECRET` | No | — | Secret used to authenticate scheduled requests (for example, Vercel Cron) |
| `EVENT_OUTBOX_RETENTION_DAYS` | No | `30` | Overrides how long cleanup keeps `events_outbox` rows |

### Setup Example

```bash
# .env.local
AUTH_SECRET="your-secret-min-16-chars"
DATABASE_URL="postgresql://user:pass@host/dbname"
ALLOWED_ORIGINS="https://your-app.vercel.app,https://your-app-git-main-user.vercel.app"
UNSPLASH_ACCESS_KEY="your-unsplash-access-key"
CRON_SECRET="cron-secret-for-vercel"
EVENT_OUTBOX_RETENTION_DAYS="30"
```

### Database Setup

Get a PostgreSQL connection string from your provider:

1. Create a database with your preferred provider, such as Supabase, Neon, Railway, or self-hosted PostgreSQL
2. Copy connection string: `postgresql://[user]:[password]@[host]/[dbname]`
3. Set as `DATABASE_URL`

### Local Development Port

`npm run dev` defaults to `http://localhost:3000`. If you need a different local port, set `PORT=` in `.env.local` before starting the dev server. `PORT` is a local development override, not part of the runtime env schema or `.env.example`.

## preqstation-skill

Agent-side variables for shell-helper mode and the legacy local stdio bridge. The recommended remote `/mcp` setup for Claude Code, Codex, and Gemini CLI uses OAuth and does not require exporting these variables just to register the server.

| Variable | Required | Default | Purpose |
|----------|----------|---------|---------|
| `PREQSTATION_API_URL` | Compatibility only | — | PreqStation web app API base URL (e.g., `https://preqstation.example.com`) for shell-helper mode or legacy local bridge flows |
| `PREQSTATION_TOKEN` | Compatibility only | — | Bearer token (format: `preq_` prefix, from `/api-keys` page) for shell-helper mode or legacy local bridge flows |
| `PREQSTATION_ENGINE` | No | `codex` | Fallback engine when client auto-detection unavailable |

### Compatibility Setup Example

```bash
# ~/.zshrc or ~/.bashrc
export PREQSTATION_API_URL="https://preqstation.example.com"
export PREQSTATION_TOKEN="preq_xxxxxxxxxxxxxxxxx"
export PREQSTATION_ENGINE="claude-code"  # optional
```

### Getting a Compatibility Token

Use this only when shell-helper mode, direct REST automation, or an older local bridge still depends on bearer-token authentication:

1. Deploy the PreqStation web app
2. Log into web UI
3. Go to Settings → API Keys or `/connections?legacy=1`
4. Click "New Token"
5. Copy the generated token (starts with `preq_`)

### Engine Values

| Value | Meaning |
|-------|---------|
| `claude-code` | Claude Code |
| `codex` | Codex (OpenAI) |
| `gemini-cli` | Gemini CLI |

## PREQ CLI Dispatcher

Execution layer variables for `preqstation install`, `preqstation setup`, Hermes, and detached worktree management.

| Variable | Required | Default | Purpose |
|----------|----------|---------|---------|
| `PREQSTATION_DISPATCH_HOME` | No | `~/.preqstation-dispatch` | Base directory for dispatcher state, logs, project mappings, and worktrees |
| `PREQSTATION_PROJECTS_FILE` | No | `<dispatch-home>/projects.json` | Project key to local checkout mapping file |
| `PREQSTATION_WORKTREE_ROOT` | No | `<dispatch-home>/worktrees` | Root directory for isolated task worktrees |
| `PREQSTATION_WORKER_HOME` | No | `<dispatch-home>/workers` | Base directory for worker support files |
| `PREQSTATION_CLAUDE_HOME` | No | runtime default | Claude-specific worker home override |
| `PREQSTATION_CODEX_HOME` | No | runtime default | Codex-specific worker home override |
| `PREQSTATION_GEMINI_HOME` | No | runtime default | Gemini-specific worker home override |
| `PREQSTATION_MEMORY_PATH` | No | — | Optional legacy memory file used as a project mapping fallback |
| `PREQSTATION_REPO_ROOTS` | No | `~/projects` | Colon-separated roots scanned by `preqstation setup auto` |
| `PREQSTATION_SERVER_URL` | No | — | PreqStation web app URL used by setup helpers |
| `PREQSTATION_API_URL` | No | — | API base URL for shell-helper mode or legacy token compatibility |
| `PREQSTATION_TOKEN` | No | — | Bearer token for shell-helper mode or legacy token compatibility |

### Setup Example

```bash
# ~/.zshrc or ~/.bashrc
export PREQSTATION_DISPATCH_HOME="$HOME/.preqstation-dispatch"
export PREQSTATION_WORKTREE_ROOT="$HOME/.preqstation-dispatch/worktrees"
export PREQSTATION_REPO_ROOTS="$HOME/projects:$HOME/work"
```

### Worktree Root Considerations

**Default:** `~/.preqstation-dispatch/worktrees`
- Persistent under the dispatcher home
- Keeps detached task worktrees together with dispatcher state
- Works for Hermes hosts using the PREQ CLI

**Custom:** `/home/user/preq-worktrees`
- Persistent across reboots
- Useful for debugging and inspection
- Requires manual cleanup of old worktrees

**In CI/CD:**
```bash
export PREQSTATION_WORKTREE_ROOT="/workspace/preq-worktrees"
```

## Environment Variable Scope

| Layer | Variables | Scope |
|-------|-----------|-------|
| **Web Service** | `AUTH_SECRET`, `DATABASE_URL`, `ALLOWED_ORIGINS`, `UNSPLASH_ACCESS_KEY`, `CRON_SECRET`, `EVENT_OUTBOX_RETENTION_DAYS` | Server-side only, set during deployment |
| **Local Development** | `PORT` | Read by `npm run dev` to override the local web-app port |
| **Shell Helper / Legacy Bridge** | `PREQSTATION_API_URL`, `PREQSTATION_TOKEN`, `PREQSTATION_ENGINE` | Available to the token-based shell helper flow and legacy local MCP bridge |
| **CLI Dispatcher** | `PREQSTATION_DISPATCH_HOME`, `PREQSTATION_PROJECTS_FILE`, `PREQSTATION_WORKTREE_ROOT`, `PREQSTATION_WORKER_HOME`, `PREQSTATION_CLAUDE_HOME`, `PREQSTATION_CODEX_HOME`, `PREQSTATION_GEMINI_HOME`, `PREQSTATION_MEMORY_PATH`, `PREQSTATION_REPO_ROOTS`, `PREQSTATION_SERVER_URL` | Controls CLI installer state, project mapping, worker homes, repo scans, and detached worktree execution |

After changing web service variables, restart or redeploy the web app. After changing dispatcher variables, restart Hermes or the long-running host process so it inherits the new environment.

## Secrets Best Practices

1. **Never commit secrets** — Use `.env.local` (git-ignored)
2. **Use secret managers** — GitHub Secrets, deployment platform env vars, HashiCorp Vault
3. **Rotate tokens regularly** — Revoke old tokens from `/api-keys` page
4. **Scope tokens narrowly** — Use separate tokens per environment
5. **Monitor token usage** — Check audit logs for suspicious activity
