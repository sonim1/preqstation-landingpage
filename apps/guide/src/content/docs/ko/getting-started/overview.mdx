PreqStation은 AI 에이전트 기반 개발 워크플로우를 위한 실행 플랫폼입니다. 웹 control plane, PREQ CLI, 선택적 dispatch integration, 에이전트용 API로 개발자와 코딩 에이전트를 연결합니다.

시스템 다이어그램보다 먼저 제품 이야기부터 보고 싶다면 [철학](/guide/ko/getting-started/philosophy/) 문서를 먼저 읽으세요.

이 페이지는 각 구성요소가 어떻게 연결되는지 이해하고 싶을 때 읽으세요. 첫 runtime 연결이 목표라면 먼저 [빠른 시작](/guide/ko/getting-started/quick-start/)을 완료하고 `status` 출력이 이해된 뒤 돌아오는 편이 좋습니다.

## 추천 첫 단계

처음 PreqStation을 설정한다면 [빠른 시작](/guide/ko/getting-started/quick-start/)부터 시작하세요. `npx -y @sonim1/preqstation@latest install`에서 시작해 로컬 runtime, MCP, project setup을 확인합니다. 웹 앱을 self-hosting하거나 migration을 검증한다면 [웹 앱 설정](/guide/ko/web-app/setup/)을 참고하세요.

## 설정 경로 순서

- **CLI 기본 설정** — 가장 빠른 CLI installer 경로는 [빠른 시작](/guide/ko/getting-started/quick-start/)
- **Worker-only 설정** — Claude, Codex, Gemini worker를 수동 설정하려면 [워커 설치](/guide/ko/skill/installation/)
- **디스패처 설정** — 웹 앱에서 queued dispatch가 필요할 때만 추가: [Telegram 연동](/guide/ko/web-app/telegram/)
- **웹 앱 설정** — self-hosting, migration, 첫 로그인 세부 정보는 [웹 앱 설정](/guide/ko/web-app/setup/)

## 핵심 시스템과 dispatch 경로

PreqStation은 task를 시작하는 trigger 경로와 실제 작업을 수행하는 engine을 분리합니다.

<CardGrid>
  <Card title="PreqStation 웹 앱" icon="setting">
    Task와 control plane입니다. 태스크 관리, 칸반 UI, workflow state, review evidence, REST/MCP 기반 API, 필요할 때 dispatch target 선택을 담당합니다.
  </Card>
  <Card title="PREQ CLI" icon="rocket">
    사용자-facing package와 command는 `@sonim1/preqstation`, `preqstation`입니다. Operator host 지원을 설치/업데이트하고, `status`와 `doctor`를 확인하고, project mapping과 worker runtime support를 준비합니다.
  </Card>
  <Card title="Worker runtimes" icon="approve">
    Claude Code, Codex CLI, Gemini CLI가 실제 task work를 수행합니다. Task의 `engine`이 어떤 worker runtime을 실행할지 결정하며, Hermes/Telegram dispatch 경로와는 별개입니다.
  </Card>
  <Card title="Integrations" icon="puzzle">
    Hermes Agent와 Telegram은 queued 또는 chat-driven delivery entrypoint입니다. Worker runtime을 대체하지 않고 operator host의 PREQ CLI로 작업을 넘깁니다.
  </Card>
  <Card title="MCP" icon="link">
    에이전트-facing API bridge입니다. 현대적인 설정은 보통 remote `/mcp` endpoint와 browser OAuth를 사용합니다. Token/API key 설정은 shell-helper mode와 예전 local bridge flow의 compatibility path로 남아 있습니다.
  </Card>
</CardGrid>

일부 legacy identifier는 호환성을 위해 아직 `preqstation-dispatcher`를 언급할 수 있습니다. 별도의 사용자-facing 설정 경로가 아니라 내부 호환성 이름으로 보면 됩니다.

<Aside>
공개 canonical 저장소는 `sonim1/preqstation`입니다. 다만 웹 앱 소스는 아직 그쪽으로 완전히 옮겨지지 않아, 로컬 설정 문서에서는 당분간 현재 개발 저장소를 함께 안내합니다.
</Aside>

## 데이터 흐름

가장 짧은 lifecycle은 아래와 같습니다.

```text
태스크 생성 -> 태스크 계획 -> worker 구현 -> Ready 제출 -> 검증 -> Done
```

### 태스크 생성

```text
사용자가 칸반 UI에서 태스크를 생성
  -> PreqStation 웹 앱이 PostgreSQL에 저장
  -> 필요하면 dispatch target 선택
  -> 필요할 때만 Hermes/Telegram relay 큐 생성
```

### Dispatcher target과 engine의 차이

- Dispatch target은 task를 Hermes 또는 Telegram relay로 어떻게 시작할지 결정합니다.
- `engine=claude-code | codex | gemini-cli`는 dispatcher와 별개이며, 실제로 어떤 CLI를 실행할지 정합니다.

### 에이전트 실행 경로

```text
Hermes/Telegram 경로:
  개발자가 web app dispatch action을 선택하거나 Hermes/Telegram으로 전달
    -> integration이 operator host로 요청 전달
    -> PREQ CLI가 프로젝트 + 태스크 + 엔진 해석
    -> 격리된 git worktree 생성
    -> 요청된 코딩 에이전트 실행
```

## 기술 스택

| 레이어 | 기술 |
| ---------- | ------------------------------------------- |
| Framework  | Next.js 16 (App Router)                     |
| UI         | React 19, Mantine 8, Tabler Icons, Recharts |
| ORM        | Drizzle ORM                                 |
| Database   | PostgreSQL (Row Level Security)             |
| Validation | Zod                                         |
| Auth       | Session cookies (HMAC-signed), bcryptjs     |

<Aside>
모든 데이터는 PostgreSQL RLS를 통해 단일 owner 기준으로 격리됩니다. 현재 PreqStation은 개인 개발자 사용 흐름에 맞춰 설계되어 있습니다.
</Aside>
