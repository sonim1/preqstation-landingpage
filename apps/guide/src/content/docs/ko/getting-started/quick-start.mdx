빠른 시작은 첫 실행 경로입니다. 목표는 하나입니다. 이 머신이 선택한 agent runtime을 통해 PREQ 작업을 실행할 준비가 됐는지 확인하는 것입니다.

## 권장 설정 경로

먼저 PREQ CLI installer를 실행하세요. 이 흐름은 로컬 operator host를 준비하고, worker runtime을 감지하고, 선택한 dispatch entrypoint를 설치하고, project mapping을 만듭니다.

```bash
npx -y @sonim1/preqstation@latest install
npx -y @sonim1/preqstation@latest status
```

installer는 다시 실행해도 괜찮습니다. 이미 설치된 항목을 확인하고, 부족한 설정만 제안합니다.

## 성공 기준

첫 실행 뒤 `status`에서 아래를 확인할 수 있어야 합니다.

- `preqstation` command 또는 반복 가능한 `npx` command를 사용할 수 있음
- Claude Code, Codex, Gemini CLI 같은 worker runtime 중 하나 이상이 감지됨
- 이 host가 queued dispatch를 받을 예정이라면 project mapping이 준비됨
- 직접 agent client가 PREQ MCP tool을 호출하는 compatibility setup을 선택한 경우에만 원격 `/mcp` 연결이 등록됨

어떤 항목이 불명확하면 더 자세한 read-only 진단을 실행하세요.

```bash
npx -y @sonim1/preqstation@latest doctor
```

Global install, `update`, `doctor`, JSON output, project mapping, Hermes targeted install, Hermes sync, uninstall까지 전체 명령 reference는 [PREQ CLI](/guide/ko/getting-started/preq-cli/)를 참고하세요.

## 내 상황에 맞는 경로 선택

| 상황 | 먼저 할 일 | 필요할 때만 추가 |
|---|---|---|
| PreqStation을 처음 설정하는 경우 | [PREQ CLI](/guide/ko/getting-started/preq-cli/) | 수동 worker-only 설정 |
| Claude Code, Codex, Gemini를 이미 직접 쓰는 경우 | [워커 설치](/guide/ko/skill/installation/) | hosted dispatch support가 필요하면 PREQ CLI |
| 웹 앱을 self-hosting하거나 migration을 검증하는 경우 | [웹 앱 설정](/guide/ko/web-app/setup/) | 로그인 확인 후 PREQ CLI |
| Telegram 또는 Hermes dispatch를 운영하는 경우 | [PREQ CLI](/guide/ko/getting-started/preq-cli/) 후 [Telegram](/guide/ko/web-app/telegram/) | 수동 profile fallback |
| 예전 token 기반 설정을 유지 중인 경우 | [레거시 API Keys](/guide/ko/web-app/api-keys/) | runtime이 지원하면 원격 `/mcp` OAuth |

## 수동 Direct-client MCP 설정

agent client가 PREQ MCP tool을 직접 호출해야 할 때만 사용하세요. Detached dispatch worker는 PREQ CLI instruction file과 task command를 사용합니다.

```bash
# Claude Code
claude mcp add -s user --transport http preqstation https://<your-domain>/mcp

# Codex
codex mcp add preqstation --url https://<your-domain>/mcp

# Gemini CLI
gemini mcp add --scope user --transport http preqstation https://<your-domain>/mcp
```

브라우저 OAuth 흐름이 뜨면 완료합니다. Codex는 `add` 중에 바로 시작하는 경우가 많고, Claude Code는 첫 실제 요청이나 `claude mcp get preqstation`에서 시작되는 경우가 많습니다. Gemini CLI는 등록 시점이나 첫 실제 호출에서 시작될 수 있습니다.

## 같은 설정 경로로 이어가기

- **Worker-only 수동 설정** — direct-client MCP compatibility가 필요할 때만 [워커 설치](/guide/ko/skill/installation/)를 참고하세요
- **Hermes Telegram dispatcher** — Hermes가 Telegram dispatch를 받아야 한다면 [Telegram 연동](/guide/ko/web-app/telegram/)을 참고하세요
- **Self-hosted 웹 앱** — 환경 변수, migration, 첫 로그인 세부 정보는 [웹 앱 설정](/guide/ko/web-app/setup/)을 참고하세요
- **레거시 token 호환성** — shell-helper 모드나 예전 local bridge가 아직 bearer token을 요구할 때만 [레거시 API Keys](/guide/ko/web-app/api-keys/)를 참고하세요

터미널에서 직접 worker access만 필요하다면 CLI 설치와 MCP 상태 확인까지만 하고 멈추면 됩니다.
