현재 구현 상태와 맞는 전체 예시는 [영어 Troubleshooting](/guide/reference/troubleshooting/)을 기준으로 유지됩니다. 아래는 가장 자주 막히는 지점을 빠르게 찾기 위한 한국어 요약입니다.

## 증상별 시작점

| 증상 | 먼저 볼 곳 | 첫 명령 |
|---|---|---|
| Claude, Codex, Gemini에 PREQ tools가 보이지 않음 | Remote MCP & OAuth | `preqstation status` |
| browser auth가 끝나지 않음 | Remote MCP & OAuth | `claude mcp get preqstation` 또는 runtime별 equivalent |
| dispatch가 project checkout을 못 찾음 | Project Mapping | `preqstation setup status` |
| Hermes는 메시지를 받지만 작업을 실행하지 않음 | Dispatcher Execution | `preqstation status hermes` |
| 내 terminal에서는 worker CLI가 되지만 Hermes에서는 실패함 | Host PATH / environment | `preqstation doctor` |
| task worktree에서 `npm install`이 실패함 | Build & Compilation | package manager log 확인 |
| shell helper가 `401 Unauthorized`를 반환함 | Legacy Compatibility | `PREQSTATION_TOKEN` 확인 |

## 먼저 doctor/status 실행

수동으로 runtime이나 MCP 설정을 뜯어보기 전에 PREQ CLI 진단부터 실행하세요.

```bash
preqstation doctor
preqstation status
preqstation doctor --json
preqstation status --json
```

일반 출력은 사람이 직접 확인할 때 쓰고, JSON 출력은 report, script, monitoring에 구조화된 진단을 넘길 때 사용합니다.

## 주요 확인 순서

1. Server URL과 remote `/mcp` endpoint가 올바른지 확인합니다.
2. OAuth login flow가 끝났는지 확인합니다.
3. Direct-client MCP compatibility를 쓰는 경우에만 Claude Code, Codex CLI, Gemini CLI의 MCP registration을 확인합니다.
4. `preqstation setup status`, `preqstation setup auto`, `preqstation setup set`으로 local project mapping을 확인합니다.
5. `claude`, `codex`, `gemini` 실행 파일이 host process `PATH`에서 보이는지 확인합니다.
6. `fnm` 같은 session-scoped Node 설정에만 의존했다면 host process 환경을 고치고 Hermes를 재시작합니다.
7. Hermes profile에 terminal/tool execution이 켜져 있는지 확인합니다.
8. `PREQSTATION_TOKEN`과 `/api-keys`는 shell-helper mode 또는 legacy local bridge compatibility path에서만 확인합니다.
9. Global CLI failure는 `~/.preqstation/logs/error.log`를 확인하고, stack trace가 필요하면 `--debug` 또는 `PREQSTATION_DEBUG=1`을 사용합니다.

전체 단계와 예시는 [영어 Troubleshooting](/guide/reference/troubleshooting/)을 참고하세요.
