칸반 보드는 태스크를 관리하는 메인 인터페이스입니다. 활성 워크플로우 컬럼은 Inbox, Todo, Hold, Ready, Done 다섯 개입니다.

아직 로컬 설치와 로그인, 에이전트 연결을 끝내지 않았다면 먼저 [빠른 시작](/guide/ko/getting-started/quick-start/) 또는 [웹 앱 설정](/guide/ko/web-app/setup/)부터 진행하세요.

칸반은 workflow position을 보는 화면입니다. 태스크 내부의 실행 기록은 [워크 그래프](/guide/ko/web-app/work-graph/)에서 확인합니다.

## 상태 의미

| 상태 | 의미 | 액션 |
|---|---|---|
| **Inbox** | 새 태스크, 아직 계획 전 | 에이전트가 보통 `preqstation task plan`으로 계획을 업로드 |
| **Todo** | 계획 완료, 에이전트 작업 가능 | `preqstation task start`로 작업 claim |
| **Hold** | 막혔거나 일시정지 | blocker 해결 후 재개 |
| **Ready** | 구현 완료, 검증 대기 | 검증 후 `preqstation task review` 또는 UI로 Done 이동 |
| **Done** | 검증 완료 | 필요 시 재오픈 또는 archive |

Archived는 활성 보드에 보이지 않으며 수동 archive 흐름으로 다뤄집니다.

## 칸반과 워크 그래프

칸반은 "이 태스크가 지금 어떤 상태인가?"에 답합니다. 워크 그래프는 "에이전트가 무엇을 했고, 어떤 evidence를 남겼고, 왜 그 workflow를 골랐는가?"에 답합니다.

보드는 task review state를 단순하게 유지합니다. 그래프는 `in_progress` 같은 별도 컬럼을 만들지 않고 실행 기록을 자세히 남깁니다.

## 첫 태스크 데모 흐름

설정 후에는 작은 태스크 하나로 아래 흐름을 확인하세요.

1. **+ New Task**를 눌러 title, description, engine, acceptance criteria를 채웁니다.
2. 계획 전에는 **Inbox**에 둡니다.
3. 구현 경로가 명확해지면 **Todo**로 이동합니다.
4. Dispatch 또는 start 후 카드에 `Queued` 또는 `Working` overlay가 표시될 수 있습니다.
5. 결과가 올라오면 **Ready**에서 검토하고, 필요하면 QA를 실행한 뒤 검증 후 **Done**으로 이동합니다.

성공한 상태는 컬럼이 review state를 보여주고, overlay가 실행 상태를 별도로 보여주는 상태입니다.

## Ready Lane QA

Ready lane에서는 project branch별 QA run을 확인할 수 있습니다. Ready task의 QA action으로:

- queue 전에 engine을 선택합니다
- 해당 project/branch의 run history를 확인합니다
- `queued`, `running`, `passed`, `failed` 상태를 구분합니다
- task workflow state와 QA run state를 분리해 봅니다

QA queueing은 Telegram을 통해 Hermes dispatch command를 보내므로 Telegram 설정이 먼저 필요합니다.

## 태스크 생성

`+ New Task`를 눌러 생성합니다.

1. **Title** — 해야 할 작업
2. **Description** — 맥락과 요구사항
3. **Engine** — `claude-code`, `codex`, `gemini-cli`
4. **Priority** — `highest`, `high`, `medium`, `low`, `lowest`
5. **Labels** — 예: `backend`, `urgent`
6. **Acceptance Criteria** — done의 기준

## 드래그 앤 드롭

- **Inbox -> Todo** — 계획 완료
- **Todo ↔ Hold** — 막힘/재개
- **Todo/Hold -> Ready** — 구현 완료, 검증 대기
- **Ready -> Done** — 검증 통과
- **Done -> Todo/Hold** — 후속 작업으로 재오픈

## 카드 정보

각 카드는 다음을 보여줍니다.

- **Task ID** — 예: `PROJ-123`
- **Title** — 작업명
- **Priority** — 우선순위 표시
- **Engine** — 어떤 에이전트가 작업하는지
- **Status indicator** — 현재 워크플로우 상태
- **Execution overlay** — 필요 시 `Queued` 또는 `Working`
- **QA run history** — Ready card에서는 branch별 queued/running/passed/failed 기록
- **Labels** — 사용자 태그

## Done으로 보내기 전 확인

Ready card를 Done으로 옮기기 전에 확인하세요.

- branch 또는 PR link가 제출된 변경을 가리키는지
- task result에 구현 요약과 검증 근거가 있는지
- QA run을 실행했다면 통과했거나 실패 원인을 이해했는지
- acceptance criteria가 실제로 충족됐는지
