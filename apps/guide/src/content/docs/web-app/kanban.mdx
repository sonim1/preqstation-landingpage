The Kanban board is your main interface for managing tasks. It displays the five active workflow columns: Inbox, Todo, Hold, Ready, and Done.

Kanban remains the workflow-position view. For the execution trace behind a task, use the [Work Graph](/guide/web-app/work-graph/).

## Task Statuses

| Status | Meaning | Action |
|---|---|---|
| **Inbox** | New tasks waiting for planning | Agent should upload a plan, usually through `preqstation task plan` |
| **Todo** | Planned and ready for agents | Agent can claim work with `preqstation task start` |
| **Hold** | Blocked or paused | Agent or user resolves the blocker, then retries |
| **Ready** | Implementation submitted for verification | Choose a QA engine, queue a run, review history, then use `preqstation task review` or the UI after verification |
| **Done** | Task verified and complete | Archive or reopen if needed |

Archived tasks are hidden from the active board and handled through manual archive actions.

## Kanban vs Work Graph

Use Kanban to answer "what state is this task in?" Use the Work Graph to answer "what did the agent do, what evidence did it attach, and why did it choose that workflow?"

The board keeps task review state simple. The graph keeps execution history detailed without adding extra columns such as `in_progress`.

## First Task Walkthrough

Use this quick demo flow after setup:

1. Click **+ New Task** and create a small task with a clear title, description, engine, and acceptance criteria.
2. Leave the task in **Inbox** until an agent or operator has planned it.
3. Move it to **Todo** only after the implementation path is clear.
4. Dispatch or start the task. The card may show a `Queued` or `Working` badge without changing columns.
5. Review the submitted result in **Ready**, run QA if needed, then move it to **Done** only after verification.

Success looks like a card whose workflow column tells you the review state, while its overlay tells you whether execution is queued or running.

## Ready Lane QA

The Ready lane includes QA runs for each project branch. Use the QA action on a Ready task to:

- choose the engine before queueing
- review the run history for that project and branch
- see statuses as `queued`, `running`, `passed`, or `failed`
- keep task workflow state separate from QA run state

Telegram must be configured before queueing QA runs, because the queue action sends the Hermes dispatch command through Telegram.

## Creating a Task

Click **+ New Task** to create a task:

1. **Title** — What needs to be done (concise)
2. **Description** — Context and detailed requirements
3. **Engine** — Which agent will execute: `claude-code`, `codex`, or `gemini-cli`
4. **Priority** — `highest`, `high`, `medium`, `low`, `lowest`
5. **Labels** — Custom tags for organization (e.g., `backend`, `urgent`)
6. **Acceptance Criteria** — Checklist of what "done" means

## Drag and Drop

Drag task cards between columns to update status:

- **Inbox → Todo** — Task is planned and ready
- **Todo ↔ Hold** — Pause or resume blocked work
- **Todo/Hold → Ready** — Implementation is complete and ready for verification
- **Ready → Done** — Verification passed
- **Done → Todo/Hold** — Reopen for follow-up work

## Today Focus

Pin important tasks to the **Today** section:

1. Open a task card
2. Click the **Pin** icon
3. Pinned tasks appear at the top of the board

Use this to surface your current priorities.

## Command Palette

Press `/` or `Cmd+K` to open the command palette:

- Search tasks by title or ID
- Quick-navigate to a task
- Filter by status or label

## Task Card Details

Each card shows:

- **Task ID** — Unique identifier (e.g., `PROJ-123`)
- **Title** — Task name
- **Priority** — Color-coded indicator
- **Engine** — Which agent will work on it
- **Status indicator** — Current workflow state with timestamp
- **Execution overlay** — Optional `Queued` or `Working` badge independent from the column
- **QA run history** — On Ready cards, a modal shows queued/running/passed/failed runs for the branch
- **Labels** — Custom tags

Click a card to view full details, edit, or add comments.

## What to Check Before Done

Before moving a Ready card to Done, confirm:

- the branch or PR link points to the submitted change
- the task result includes implementation notes and verification evidence
- any QA run you queued has passed or its failure is understood
- the acceptance criteria in the card are satisfied

## Bulk Actions

Select multiple tasks:

1. Hold `Cmd/Ctrl` and click cards
2. Use the action menu to:
   - Change priority
   - Add/remove labels
   - Archive completed tasks
   - Reassign engine
